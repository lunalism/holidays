## 1. 정정 — 셋 다 이 세션 안에서 잡혔다

**하나. 같은 날 순서의 사양 오류.** 사양은 "같은 날이면 kr 이 jp 앞"이라 했으나, 파일 순서의 진실은 core `assign_uids()` 의 (날짜, token) 정렬이고 같은 날은 token 사전순이라 jp 가 앞이다. 구현 보고의 관찰이 이것을 잡았고, core 를 고치지 않고 사양(docstring)이 사실을 말하게 고쳤다. Codex 리뷰가 이 판단을 제3자로 재확인했다 — "원천 결합 순서에 의존하지 않는다".

**둘. 멈춤 하나의 오배치.** CALNAME 은 SEQUENCE 로 언제든 고칠 수 있는 낮은 결정인데, 전체 구현을 세우는 멈춤을 그 앞에 뒀다. 이것은 새 규칙이 아니라 기존 원칙("멈춤은 되돌리기 어려운 결정 앞에만")의 위반 사례다 — 원칙은 있었고 프롬프트가 지키지 않았다. 낮은 결정은 규칙("kr 표기를 따른다")으로 흘려보내고 push 전 일괄 확인으로 잡는다.

**셋. README 대체 문장의 사실 오류.** "data/kr 은 자리만 유지" 문장의 삭제를 Codex 가 "뺌 목록 누락"으로 지적했다. 실측(ls, git ls-files, git log)이 지적을 재분류했다 — 삭제된 문장이 참이었고, 대체한 문장("kr 은 없다")이 거짓이었다. 지적의 분류를 지적자의 분류대로 받지 않고 실측으로 재분류한 사례다. 근본 원인은 판단 목록의 분류에 [대체]가 없었던 것이다 — 대체는 [남김]도 [뺌]도 아니며, 대체야말로 옛 문장과 새 문장이 같은 사실을 말하는지 검사가 필요한 곳이다.

## 2. 검토했다가 버린 갈래

이 문서의 핵심이다. 코드는 무엇을 했는지 들고 있지만 무엇을 안 했는지는 어디에도 없다.

**`cross/kr-jp.ics` 경로와 cross 토큰을 버렸다.** 상세는 #31 본문에 — 여기는 참조만 둔다.

**범위 상수화와 재현 테스트 매개변수화를 버렸다.** 동상 — #31 본문 참조.

**kr·jp 와의 UID 공유를 버렸다.** 기각 근거는 kr·cross 동시 구독 사례다 — 클라이언트 양쪽 부류(피드별 UID 격리 / 전역 UID) 모두에서 공유의 이득이 0 이고, 전역 UID 클라이언트에서는 비결정적 덮어쓰기 위험이 있다. SEQUENCE 결합 문제가 부가로 붙는다. 근거: 이 문서.

**README 를 문서에 맞추려 data/kr 디렉터리를 지우는 것을 버렸다.** §1-3 의 (나) 갈래다 — 문서 PR 이 레포를 고치는 방향 역전이라 기각했다.
