닫힌 결정:
- **주 피드 URL 은 평면형 `de_{주코드}.ics`.** 기존 여섯 피드와 동형.
- **주 피드는 주 전역 항목만.** 지자체·집단 한정(Mariä Himmelfahrt,
  Friedensfest, Buß- und Bettag 류)은 범위 밖 — de.ics 합집합 기각과
  같은 논리(안 쉬는 날이 뜨는 신뢰 훼손).
- **주 순서: BE → BY → HE → HH → NW.** BE 선행의 근거는 구조 요구사항
  최대(일회성 designated + verified 혼합) — 첫 주가 최대를 커버하면
  나머지가 진짜 판박이가 된다. 선정 자체의 근거는 방 거주자 실분포.
- **자체 YAML, de 상속 아님.** 각 주의 출처가 그 주 법조문으로 완결되고,
  16주가 차면 "교집합 == de.ics" 하니스가 독립 소스 16벌의 교차 검증이
  된다. 씨앗 테스트는 #44 에 세워져 있고 STATE_FEEDS 2개 미만 skip —
  다음 주 피드가 들어오는 순간 자동 활성화.
- **verified 2단계를 주 피드에 적용.** 발행 자격 = 조문 열거 확보 +
  독립 소스 날짜 대조. verified: true 는 공식 경로(관보·의회·공식 포털)
  확인분만. 공식 포털 4주 전멸(juris 계열 JS 셸, NRW 검색 SPA)이 이
  완화의 배경 — 문자 그대로의 "원문 확인 = 발행 자격"은 과잉이었다.
- **주 피드 UID 는 `{피드토큰}-{key}` 접두사.** §1 참조. 일반 규약으로
  승격 — BY 부터 재론 없이 적용.
- **일회성(designated) token 은 연도 접미 필수**, charset
  `[a-z][a-z_]*(?:_\d{4})?`, 로더가 key 연도 == date 연도 검사.
  BE 의 8. Mai 가 2020·2025 두 번 있어 연도 없이는 key 가 겹친다.

## 1. 정정

- **UID 충돌을 설계에서 놓쳤다.** "token 규약은 de 와 동일" 지시대로면
  전국 공통 9건의 UID 가 de.ics 와 바이트까지 같아져, 동시 구독 캘린더에서
  서로 덮어쓴다. CC 가 kr_only 전례를 근거로 접두사를 [대체] 제안, 수용.
  labor_day 충돌을 피하자며 neujahr 충돌을 만들 뻔했다 — 같은 세션 안에서
  같은 유형을 두 번째는 못 본 것.
- **holiday_11 의 "렌더러가 읽을 자리는 있다"는 낙관 서술이었다.**
  "읽을 수 있다"와 "읽고 있다"를 가르지 않았고, 실제는 렌더러가 de 를
  읽지 않는 상태였다(#43 에서 확장).
- **"기존 여섯 줄" 오기** — 랜딩 지시에서 다섯 줄을 여섯으로 셌다.
  CC 실측이 잡았다.
- **검증 명령 오류** — holiday_11 §1 에 기록된 것과 같은 유형이 재발하지
  않도록, 신규 파일의 "무영향" 단언은 diff 대상이 아니라 수정 전후
  비교로 지시할 것.

## 2. 검토했다가 버린 갈래

  주법 발견이 들어갈 자리가 없어 기각.

  자동 채움으로 나가는 경로라 차단. PR 은 항상 CC + --body-file.
- **네 주(BE·NW·HE·HH) 동시 발행**: 자격·특이점이 주마다 달라 순차로.
- **하니스 차집합 허용 목록**(BE): python-holidays 0.102 가 일회성 셋을
