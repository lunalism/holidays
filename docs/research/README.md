# docs/research — 세션을 넘는 조사 보고

## 무엇을 두는가

세션이 끝난 뒤에도 참조될 조사 보고(`report_<주제>.md`)와 그 재현 스크립트다.
스크립트와 발췌 로그는 같은 이름의 하위 폴더(`report_<주제>/`)에 둔다.
규칙·테스트 주석이 보고를 가리킬 때는 이 폴더의 경로를 쓴다 — `/tmp` 경로는
세션이 끝나면 사라진다(첫 사례: `docs/research/report_bgbl_1990_einigungsvertrag.md`).

## 보고의 흐름

- 조사 보고는 레포 밖 `~/holidays-reports/` 에 쓴다.
- 그 보고를 근거로 쓰는 구현 PR 이 보고를 `docs/research/` 로 옮긴다 — 내용은 고치지 않는다.
- 전사본·탐색 기록·스크립트는 같은 이름의 폴더(`report_<주제>/`)에 README 와 함께 둔다. PDF 는 두지 않는다.
- 그 폴더의 스크립트는 재현 기록이다 — CI 는 돌리지 않는다.
- 원본(`~/holidays-reports/` 의 파일)은 PR 머지 뒤 사람이 지운다.

첫 적용은 #112–#115 다(`report_ubuntu2604.md`·`report_nw_feiertagsgesetz_chain.md`·
`report_he_be_gazette_access.md`). AGENTS.md 「조사와 보고」가 같은 문구를 든다 — 고칠 때는
둘을 함께 고친다.

## 이차 기록이다

여기 있는 보고는 근거의 정본이 아니다. 데이터 근거의 정본은 규칙 YAML 의
`source` 필드다(`CLAUDE.md` 「데이터 근거의 정본은 커밋 메시지가 아니라 YAML 의
`source` 필드다」). 보고와 `source` 가 어긋나면 `source` 를 고치거나 정정을
적는다. 보고 자체가 틀렸을 때도 정정을 적는다. 정정은 옮긴 보고가 아니라 같은
이름의 폴더(`report_<주제>/` 또는 그 하위 폴더)의 README 에 절로 둔다 — 보고는
날짜가 박힌 기록이라 고치지 않고, 보고를 고쳐 어긋남을 감추지 않는다(첫 사례: #115,
`report_he_be_gazette_access/be_2019/README.md` 「정정 — 상위 보고의 "두 판"
서술」). 예외는 공개 레포에 둘 수 없는 값의 가림뿐이고, 가린 줄에 이유를 단다(#114).

## 넣지 않는 것

- 받은 원본(관보 PDF 등). 이 레포는 관보를 수집하지 않고(README 「독일 — 각 주
  관보」), 열람처의 재배포 조건을 확인하지 않은 파일을 공개 레포에 두지 않는다.
- 사이트 응답 덤프(HTML·JS), 헤더 덤프, 쿠키 파일, 세션·CSRF 값이 든 로그.
  필요한 로그는 그 값을 지운 발췌만 둔다. 커밋 전에 넣는 파일 전부를 대소문자
  무시로 검색한다: `_csrf`, `SID=`(빈 값 제외), `cookie`, `bgblxaver`,
  `ServiceKey`, `token`, `password`.
- 렌더 이미지·스크린샷. 크고, 보고의 문장이 그 판독 결과를 이미 담는다.

## 옮기지 못한 과거 보고

이 폴더 이전의 보고는 `/tmp/report_*.md` 에만 있었고 재부팅으로 유실됐다. 규칙
YAML·테스트 주석의 그 참조들은 그대로 둔다 — 원본이 없어 옮길 수 없고, 참조
문장 자체는 당시 근거를 어디서 읽었는지의 기록이다. 목록은 여기 적지 않는다:

    git grep -n "/tmp/report_"

## 공개된다

`docs/` 는 GitHub Pages 발행 대상이다(`_config.yml` 은 `landing/` 만 exclude 하고,
`docs/seo.md` 「exclude 는 공개 웹 주소였던 적이 없는 경로에만 쓴다」에 따라
`docs/` 를 빼지 않는다). 따라서 이 폴더의 파일은 공개 URL 로 열린다. 크롤은
`robots.txt` 의 기본 차단이 막지만 색인 자체를 막지는 않는다. 위 「넣지 않는
것」은 그 전제에서 정한 것이다.
