## 1. 판단이 갈린 지점

### 1-1. 프롬프트의 전제가 세 번 틀렸고, 셋 다 실측이 잡았다

프롬프트가 적은 사실도 이차 소스다. 세 번 다 선행 실측 절이 그물이었다.

- **"지금 CI 가 네트워크에 기대는 것은 캐시 미스 때뿐"** — `docs/browser-smoke.md`
  의 서술이자 조사 프롬프트의 전제. 조사 보고가 run 로그로 뒤집었다: 캐시가
  적중해도 크기가 1 KB 남짓이고 wheel 을 매 run 받는다(`setup-uv` 의
  `prune-cache` 기본값). #106 이 문서를 고쳤다.
- **"머지 후 publish dispatch 는 캐시 미스"** — 구현 프롬프트의 예상. 실제로는
  머지 push 가 켠 ci run(35043815813)이 main 스코프 캐시를 먼저 만들었고, 뒤이은
  dispatch 는 적중이었다(§3-2 캐시 목록).
- **"`download-from-astral-mirror` 입력이 v7 에 있다"** — #108 프롬프트의 단정.
  선행 실측이 `@v7`(=v7.6.0)의 `action.yml`·`inputs.ts` 에서 그 입력을 찾지
  못했다. 그 입력은 **v8.2.0 부터**다. 최신판 `action.yml` 을 보고 대상 태그를
  열지 않은 것이다. CC 는 구현 전에 멈춰 선택지 셋을 보고했고, 사람이 A(`@v7`,
  미러 수용, 입력 없음)를 골랐다.

교훈: 대상 버전의 원문을 연다. "다르면 구현 전에 멈춘다" 는 절이 있어서 세
번째가 워크플로에 존재하지 않는 입력으로 들어가지 않았다.

### 1-2. 검사 문장이 맞아도 구현이 뚫릴 수 있었다

`docs/browser-smoke.md` 의 셋은 #104 시점에 이미 맞는 문장이었다. 그런데 문장
그대로 구현하면 두 사고 다 놓칠 수 있었다는 것이 조사에서 드러났다.

- "콘솔 오류 0" 을 콘솔 이벤트로만 세면 두 사고 모두 0 이었다. #92 형은 미처리
  예외(`pageerror`)로만 오고, #83 형은 아무 오류도 내지 않는다.
- #83 형은 스크립트의 블록별 예외 처리가 삼키고 컨테이너를 숨긴다. 콘솔·예외·
  행 수 전부 정상이고, 잡는 것은 **숨겨진 컨테이너 안에 남은 DOM 속성** 하나다.
  가시성 기준 질의는 0 을 돌려 통과한다.

기대 문서의 문장을 구현 기준으로 좁힌 것이 #106 이고, 그 기준이 리팩터로 풀리지
않게 메타 테스트로 고정한 것이 #107 이다 — 검출기가 그 신호를 내는지 단언하고
"검사가 실패했다" 로 단언하지 않는다. 빨강 재현으로 확인했다: 잔여 질의를
가시성으로 바꾸면 #83 메타가, `pageerror` 수집을 빼면 #92 메타가, 외부 대체를
차단으로 바꾸면 세 면이 빨개진다.

## 3. 레포 밖에서 확인된 것

### 3-1. 러너와 액션 (조사 보고·선행 실측 중 코드·문서에 없는 것)

  `channel` 을 버렸다(§2).

  포트로 바꿔 재실행 — 있는 브라우저는 exit 0, 없는 브라우저는 ECONNREFUSED.
- **setup-uv v7.6.0 의 두 경로(소스 읽기로 판정).** uv 다운로드는 미러 실패 시
  GitHub Releases 로 되돌아간다 — `src/download/download-version.ts` 의 경고
  원문 "Failed to download from mirror, falling back to GitHub Releases". **버전
  목록 조회에는 폴백이 없다** — `src/download/versions-client.ts` 의
  `fetchVersionData` 는 응답이 ok 가 아니면 "Failed to fetch version data" 로
  던지고, `src/utils/fetch.ts` 는 프록시만 붙일 뿐 재시도가 없다. 이 레포는 uv
  버전을 고정하지 않아(`latest`) 매 run 이 조회를 탄다 — §5.
- **setup-uv v8 이후 태그 체계.** v8.0.0 릴리스 "No more major and minor tags".
  `v8`·`v9`·`v10` 참조는 Not Found. 정확한 버전 태그만 있다.
- **`pages-build-deployment` 의 Node 20 경고는 이 레포가 고칠 수 없다.** 경로가
  `dynamic/pages/pages-build-deployment` 인 GitHub 관리 워크플로이고, 경고 대상은
  `actions/upload-artifact@v4` 다. 레포의 워크플로 파일은 `ci.yml`·`publish.yml`
