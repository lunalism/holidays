## 1. 정정 — 둘 다 이 세션의 조사·구현이 잡았다

**하나. status.json 을 재현의 입력으로 단정했었다.** 실제는 대조물이다 — 재현 입력 셋(today·dtstamp·previous)은 전부 발행본 자신에서 나온다(`tests/test_published_feed.py` 의 모듈 docstring 이 정본). 조사 1 이 이것을 뒤집었고, 그 사실이 #24 의 판정 구조가 됐다 — 스키마 변경이 바이트 재현 단언을 건드리지 않는다는 것을 알았기에 "값 보존" 셋만 확인하면 됐다.

**둘. 소비자 전수를 파일명 grep 으로 잡아 dict 소비자를 놓쳤다.** 조사 1 은 `status\.json` 으로 grep 했고, 파일을 열지 않고 `status()` 반환 dict 를 직접 읽는 `tests/test_pipeline.py` 가 빠졌다. 커밋 도중 KeyError 로 드러나 그 자리에서 잡았다. **파일 소비자와 스키마 소비자는 다른 집합이다** — 스키마 소비자는 키 이름으로 찾아야 한다. #24 커밋 본문에 다섯 소비자가 기록돼 있다.

줄번호 좌표의 수명도 여기 붙여 둔다. 이 세션이 고친 포인터 두 개는 고치는 커밋 자신이 좌표를 다시 밀었다 — 지시된 값이 아니라 이동 후 재계수 값을 적었다. 좌표는 옮겨 적는 순간부터 낡기 시작한다.

## 2. 검토했다가 버린 갈래

이 문서의 핵심이다. 코드는 무엇을 했는지 들고 있지만 무엇을 안 했는지는 어디에도 없다.

**expand/contract 를 버렸다.** feed 단수를 남긴 채 feeds 를 병행하고 나중에 제거하는 3단계는 보장이 세지만, PR 셋에 이중 키 발행 기간이 생기고 마지막 제거 단계가 결국 같은 리스크를 진다. 소비자 전부가 이 레포 안에 있는 솔로 레포에서는 값이 안 나온다. #24 는 한 번에 갔고, 판정 기준 셋이 단계적 보장의 자리를 대신했다. 근거: #24 본문.

**status/kr.json 파일 분리를 버렸다.** 나라별 파일이면 조립자가 필요 없지만, 랜딩의 fetch 가 둘이 되고, 갱신 시각의 진실 공급원이 모호해지고(어느 generated_at 이 "마지막 갱신"인가), 재현 테스트도 둘이 된다. 파일 하나에 국가 키가 낫다. 근거: 이 문서.

**워크플로 반복문화와 jp 편입을 한 PR 로 하는 것을 버렸다.** 워크플로는 pytest 가 없는 영역이라, 깨졌을 때 반복문 탓인지 jp 탓인지 로그로만 갈라야 한다. #25(kr 하나로 반복문을 만들고 동작 불변을 실측)와 #26(목록에 한 단어)으로 나눴다 — 이전 세션 #20/#21 의 "복제 먼저, 이동 따로"와 같은 논리다. 근거: #25 본문.

**SUMMARIES 를 단일 나라에도 접두사 포함으로 쓰는 것을 버렸다.** "kr: …" 접두사가 붙으면 kr 단독 커밋 메시지가 현행과 달라진다. 불변 조건이 우선이다 — 하나면 접두사 없는 요약(스코프가 이미 나라를 말한다), 여럿이면 "kr: …; jp: …". 근거: publish.yml 주석과 #25 본문.

**커밋 스텝의 빈 FEEDS 가드 생략을 버렸다.** 생성 스텝에만 두면 되지 않느냐 — 안 된다. 커밋 스텝은 `always()` 라 생성 스텝이 실패하거나 건너뛰어져도 들어온다. 도달 불가 코드가 아니라 실제 경로다. 두 곳 다 두었다. 근거: publish.yml 의 가드 주석.

**kr 주력 제목 유지 + jp 부기를 버렸다.** "대한민국 공휴일 캘린더 (일본도)" 류는 나라가 늘 때마다 제목을 재론하게 된다. 제목을 일반화하고 나라는 본문이 말한다. 근거: #26 커밋 `9111522`.

## 3. 레포 밖에서 확인된 것

- **GitHub Actions `run:` 의 기본 셸은 `bash -e {0}` 다** — errexit 이 기본으로 켜져 있다. publish.yml 이 `set -o pipefail` 만 따로 켜는 이유가 그 증거다(-e 는 기본에 있고 pipefail 은 없다). Codex 의 "다국가에서 중간 나라 실패가 은폐된다" 지적을 기각한 근거이고, 러너 조건 재현(-e 유/무 비교)으로 확인했다. 기록: #25 본문.
- (이월 확인) `workflow_dispatch` 가 publish.yml 에 있어 cron 을 기다리지 않는 실측이 가능했다 — 이 세션에서 세 번 썼다.

## 4. Codex 리뷰의 자리

#25 에서 [high] 하나가 반은 틀리고(errexit 부재 전제) 반은 맞았다(빈 FEEDS). 틀린 반을 기각한 근거와 맞은 반의 수용(가드 커밋 `b765d51`)이 둘 다 PR 본문에 있다. 리뷰 지적을 통째로 받지도 통째로 버리지도 않고 갈라서 판정한 첫 사례다 — 그리고 기각에는 반드시 재현이 붙었다. 러너 조건을 로컬에서 재현해 지적의 전제가 이 환경에서 성립하지 않음을 보이고 나서 기각했다.
