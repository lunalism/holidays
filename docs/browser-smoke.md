# 브라우저 스모크 — 기대와 경계

`render()` 가 낸 페이지가 **브라우저에서 성립하는가**를 본다. 무엇을 잡고
무엇을 잡지 않을지, 어디서 돌고 실패가 무엇을 뜻하는지를 적는다. 구현은
이 문서를 근거로 한다. 구현이 이 문서와 어긋나면 구현이 틀린 것이고,
기대를 바꾸려면 이 문서를 먼저 고친다.

## 이 축이 무엇인가

랜딩 테스트는 다섯 파일 155 건이다 — `test_landing.py` 47, `test_landing_contract.py`
69, `test_landing_render.py` 3, `test_landing_head.py` 19, `test_landing_og.py` 17.
전부 문자열·구조 대조다: 정규식으로 블록을 뽑고, JSON 을 파싱하고, 바이트를
비교한다. **어느 것도 HTML 을 DOM 으로 세우거나 JS 를 실행하지 않는다.**
스크립트에 문법 오류가 있어도 155 건이 전부 초록이다.

이 축은 그 반대편이다. 페이지를 브라우저에 올리고 스크립트가 끝까지 돈
결과를 본다.

`DESIGN.md` 「마커는 선언이지 검증이 아니다」를 뒤집지 않는다. 그 결정은
마커 선언을 render 가 검증하지 않기로 한 것이다 — 검증하려면 HTML 파서와 JS
인식이 필요하고, 선언을 검증하면 선언이 무의미해진다. 이 축은 **검증하지
않기로 한 것의 결과를 보는 자리**다. 선언이 틀리면 render 는 멈추지 않고
깨진 페이지를 내지만, 그 페이지는 브라우저에서 깨진다. 둘은 짝이다 — 앞은
입력을 믿고, 뒤는 결과를 본다.

## 무엇을 잡는가 — 셋

범위를 좁게 둔다. 검사되지 않는 런타임 동작은 열 가지가 넘지만(복사, 날짜
표기, 복수형 갈래, 경고 표시, noscript, 시각 상태 …) 전부 잡으려 하면 render
의 입력 계약에서 겪은 「수렴하지 않는 급수」를 다른 축에서 반복하게 된다.
스모크는 "페이지가 성립하는가" 까지다.

- **JS 가 파싱되고 오류 없이 끝까지 돈다.** 콘솔 오류 0. 스크립트는
  IIFE 하나이고, 구독 절을 동기로 세운 뒤 `fetch` 로 상태를 채운다 — 그
  전 구간에 미처리 예외가 없어야 한다.
- **구독 행 수가 데이터의 피드 수와 같다.** `feed-data` 블록의 피드 수와
  스크립트가 세운 행 수가 같다. **실제로 이 자리에서 15 → 0 이 발행됐다**
  (PR #92) — 문구의 `</script>` 가 JSON 블록을 일찍 닫아 JS 경로의 목록이
  통째로 사라졌고, noscript 는 멀쩡해서 봇만 살았다. 그때의 테스트는 전부
  초록이었다.
- **상태를 먹인 뒤 `data-pending` 이 모두 사라진다.** 상태 블록의 값 자리는
  `data-pending` 을 달고 "불러오는 중" 으로 나가고, 스크립트가 값을 넣으며
  그 속성을 뗀다. 하나라도 남으면 그 블록은 영원히 "불러오는 중" 이다.
  **실제로 이 자리에서 "CI 녹색인데 구독자는 숫자를 못 봄" 이 났다**
  (PR #83) — 복수형 갈래 하나가 빠져 `fmt` 가 `undefined` 에 걸렸다.

뒤의 둘은 가정이 아니라 과거의 실물 사고다. 두 번 다 render 는 돌았고
테스트는 초록이었고 페이지는 깨졌다. 이 축이 없어서 사람이 headless 로
보고서야 알았다.

## 무엇을 잡지 않는가

- **복사 동작** — secure context 와 클립보드 권한이 필요하다.
- **시각 상태**(현재 언어 링크가 굵기·밑줄·색 세 축으로 갈리는 것) —
  computed style 이 필요하며 별개 미결이다. 「더 생기면 한 번에
  배선한다」는 판단이 이미 있다.
- **`toLocaleDateString` 의 출력, `STALE_DAYS` 경고, 복수형 갈래의 결과** —
  시계 조작이나 문면 대조가 필요하다. 문면은 locale 이 들고 번역을 다듬을
  때마다 바뀐다.
- **noscript 목록의 표시 여부** — JS 를 끈 두 번째 실행이 필요하다.

빼는 이유는 중요하지 않아서가 아니다. 넣는 순간 스모크가 아니라 E2E
스위트가 되고, 그 스위트는 문면·시계·권한을 다 흉내 내야 해서 유지 비용이
검사 가치보다 먼저 자란다. 위 셋 중 무엇이 실물 사고로 나타나면 그때
「무엇을 잡는가」로 올린다 — 사고가 근거이지 가능성이 근거가 아니다.

## 무엇을 대상으로 하는가

**`render()` 의 결과물**이다. 라이브 발행본이 아니다 — 목적이 발행 전에 잡는
것이므로 발행된 것을 보는 것은 늦다. 커밋된 `index.html` 도 아니다 — 그것이
지금의 입력에서 재현되는지는 `test_landing_render.py` 가 따로 본다.

페이지의 `fetch` 는 절대경로(`/status.json`)를 쓴다. 언어 하위 경로(`/ja/`)에서
상대경로가 엉뚱한 곳을 가리키는 것을 막은 결정이고, 그래서 `file://` 로는
열 수 없다 — **로컬 서버가 필요하다.** 세 면 전부를 대상으로 한다. 상태
데이터를 어떻게 먹일지(실제 `status.json` 인지 고정본인지)는 구현 사안이며
여기서 정하지 않는다.

## 어디서 도는가

**매 PR(`ci.yml`)과 발행 run(`publish.yml`) 양쪽**이다.

발행 run 에서 도는 이유는 자명하다 — 그 run 이 랜딩을 다시 만들어 올린다.

PR 에서 도는 이유: 발행 직전에 아는 것은 늦다. PR #92 의 두 사고는 랜딩
파이프라인이 PR 열둘로 쌓인 뒤 통합 리뷰에서 발견됐고, 고치는 데 리뷰
여섯 라운드가 들었다. PR 단계에서 페이지를 세워 봤다면 첫 PR 에서
빨갰다.

## 실패하면 무엇을 의미하는가

**발행을 막는다.** 깨진 페이지를 내보내지 않는 것이 목적이다.

이것은 `published_artifact` 마커의 논리와 다르다. 그 마커는 "커밋본이 낡았다"
를 발행 run 에서 빼는데, 낡은 랜딩은 다음 발행이 고치므로 막을 이유가 없다.
스모크가 빨간 것은 낡음이 아니라 **지금 입력이 깨진 페이지를 낸다**는
것이고, 다음 발행도 같은 것을 낸다. 그래서 마커를 붙이지 않는다.

## 대가와 그 처리

이 축은 이 저장소의 성질 하나를 깬다 — **파이썬 단일 툴체인**이다. CI 는
`ubuntu-latest` 에서 uv 를 깔고 `uv sync` 로 파이썬 의존성만 받으며, 다른
런타임이 들어온 적이 없다(같은 이유로 Jekyll 빌드 검사를 기각한 기록이
있다). 브라우저 바이너리가 들어온다.

- **네트워크 의존이 하나 는다.** 바이너리 배포처가 죽으면 코드가 멀쩡해도
  빨개지고, 실패가 발행을 막으므로 발행도 막힌다. 지금 CI 가 네트워크에
  기대는 것은 체크아웃과 uv 캐시 미스 때의 패키지 취득뿐이다.
- 그래서 **바이너리를 캐시한다.** 평시에는 네트워크를 타지 않고 캐시 미스일
  때만 받는다. uv 캐시(`setup-uv` 의 `enable-cache`)와 같은 패턴이다.
- **빨간 신호를 믿지 못하게 되는 것이 가장 나쁜 결과다.** 외부 이유로
  빨개지는 일이 반복되면 안전망이 있어도 신호를 무시하게 되고, 그때
  안전망은 없는 것보다 나쁘다 — 있다고 믿으면서 보지 않는다. 이 문서가
  캐시를 요구하는 이유가 그것이다.
- **시간.** 지금 CI 는 run 당 1 분 안팎(최근 다섯 건 54 초 – 1 분 16 초)이고
  그중 거의 전부가 pytest 다. 브라우저 기동이 얹힌다. 어느 정도까지가
  받아들일 수 있는 폭인지는 구현에서 실측해 적는다.
- **flaky 를 막는 것은 작성 방식이다.** 고정 대기(`sleep`)를 쓰지 않고 조건
  대기(속성이 사라질 때까지, 행이 N 개가 될 때까지)를 쓴다. 고정 대기는
  느린 러너에서 빨개지고 빠른 러너에서 시간을 버린다.

## 이 문서가 닫지 않는 것

- 도구의 구체적 선정과 버전 고정 방식.
- 캐시 키의 구성.
- 상태 데이터를 먹이는 방법.
- **로컬에서 바이너리가 없을 때의 동작 — 실패인지 스킵인지.** 결정이
  필요하다. 스킵이면 "로컬 초록" 의 의미가 CI 와 달라진다 — 로컬에서 전부
  초록이어도 CI 에서 처음 빨개질 수 있고, 그것은 이 저장소가 이미 「로컬
  pytest 녹색 ≠ CI 녹색」으로 안고 있는 종류의 어긋남이다. 어느 쪽이든
  그 사실을 알고 정한다.
